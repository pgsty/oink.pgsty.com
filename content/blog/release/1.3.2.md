OINK 1.3.2 removes the mandatory Dart Sass installation introduced in 1.3.1.
Ordinary site builds and previews use **Hugo Extended and its built-in LibSass**.
Main styles, ReDoc styles, dark syntax highlighting, and project SCSS hooks
remain supported. All independent readability and FileTree fixes from 1.3.1
remain included.

## Build requirements {#build-requirements}

**Hugo Extended 0.168.0** is the development, CI, preview, and deployment
baseline for all maintained sites. Go is needed to resolve Hugo Modules; no
external Sass executable, Node.js, or npm is required for ordinary site builds.

Do not enable `--panicOnWarning` or `HUGO_PANICONWARNING`. Keep warnings
visible and review them. Hugo reports an upstream LibSass deprecation warning;
this known warning is accepted. Checks verify theme diagnostics and safe
fallbacks directly.

The default Hugo version stays pinned. Future upgrades must preserve the
consumer dependency boundary. A Hugo release that removes built-in LibSass
requires a separate compatibility decision.

## Upgrade {#upgrade}

Update the module pin:

```sh
hugo mod get github.com/pgsty/oink@v1.3.2
```

Commit the updated `go.mod` and `go.sum`. Remove Sass installation steps that
were added solely for OINK 1.3.1, and set the default Hugo workflow version to
`0.168.0`. Sites using a vendored theme must refresh that copy as well.

Existing content, appearance settings, and project SCSS customizations need no
migration. See the [toolchain contract](/docs/design/architecture/#hugo-toolchain).

## Validation {#validation}

The theme's focused compiler check builds real main and ReDoc styles with no
Sass executable on `PATH`. It checks project-variable and project-style hooks
and the dark Chroma palette. Hugo 0.168.0 builds with warnings visible. The
compiler checker accepts the known upstream LibSass warning and rejects
unexpected diagnostics.
