> [!IMPORTANT] Release draft
> Updated on 4 October 2026 against the changes since `v1.1.0`, including
> theme HEAD `b0af631` and subsequent working-tree changes. Version 1.2.0 has
> not been published. This site still pins `v1.1.0`; local checks use the
> sibling theme checkout. The page date is the original draft date.

OINK 1.2.0 improves the path from authoring to reading and publishing. Navigation
and metadata agree on the same pages, browser enhancements preserve content and
focus, and maintenance tools protect site sources. Existing 1.1.0 sites need
no bulk content migration or new required configuration.

## At a glance {#at-a-glance}

- Navigation trees, previous/next links, and navigation JSON use consistent scope.
- Blog pagination has page-specific canonical URLs; SEO alternates represent actual translations.
- CJK keyword matches show readable page summaries, and outline tracking handles literal percent signs.
- Landing pages remain readable without JavaScript; copying and shortcuts preserve reader focus.
- Featured images, diagram endpoints, and build-time mathematics follow their documented contracts.
- Repository actions handle Windows paths and external mounts without exposing build-machine paths.
- Snapshot and PDF tools protect inputs and restrict publication-time resource access.
- A new maintenance tool inventories consumer sites and validates exact theme upgrades.

## Navigation, metadata, and images {#navigation-and-metadata}

An explicitly empty `data/docs_nav.json` `sections` array warns and falls back
to the content tree. Both explicit and content-derived trees prune `toc_hide`
subtrees. Navigation JSON resolves `manual_link_relref` to the same internal
destination as the sidebar; manual placeholders stay out of the pager.

Each paginated Blog index uses its own canonical URL. Table-only indexes do not
acquire an unnecessary paginator. `hreflang` and Open Graph locale alternates
list actual translations. A missing translation can still send the visible
language picker to that language's home page, but that fallback is omitted from
SEO alternates. Archive pages after page 1 omit language alternates because
translated archives can have different pagination boundaries.

For file-backed pages, featured-image precedence is explicit `images`, a
page-bundle image, then inherited images. An explicitly authored value remains
explicit even when it equals a cascade value. Generated pages without a source
file treat resolved images as explicit. Non-string resource `alt` metadata
warns and is ignored, preserving the authored image alt text.

## Rendering and reader interactions {#rendering-and-interactions}

Landing content is visible before enhancement. Reveal effects hide it only
after an observer is attached, so disabled JavaScript or a failed script request
does not leave an empty page. Animated metrics finish at their authored display
string, retaining compact values, prefixes, and suffixes.

Clipboard fallback restores input or document selections, including selection
direction, and returns focus after removing its temporary control. It respects
another control that acquired focus during copying. The command palette also
recovers Tab movement when focus has moved outside it. Ctrl/Cmd+K and page
shortcuts yield to other open dialogs, including visible fixed-position ARIA
dialogs.

CJK searches that match only `search_keywords` show the page description or
excerpt instead of a synonym list. Body matches retain surrounding text. Outline
links decode valid URL fragments and use the literal heading ID for malformed
percent sequences, including headings near the page end.

PlantUML and Draw.io endpoints are validated before their runtimes load. Valid
values are HTTP(S) URLs with a host or same-site paths. Invalid types, schemes,
protocol-relative URLs, raw backslashes, whitespace, and pathless references
warn and disable the integration. A disabled PlantUML endpoint preserves its
source. Draw.io Edit and Image Zoom are separate controls; Edit remains usable
with keyboards, touch devices, and forced colors.

Mathematics remains Hugo-rendered HTML and MathML with local CSS. Generated
KaTeX class names are normalized to the vendored stylesheet on Hugo 0.160.1,
without changing TeX or MathML. Numbered-equation captions wrap on narrow
screens. Image checks use actual files and dimensions; output goldens normalize
insignificant KaTeX measurement precision across tested Hugo versions.

## Repository actions {#repository-actions}

Edit, history, and create-child links normalize physical source paths to `/`
before checking the site boundary. External mounts need an explicit
`path_base_for_github_subdir` mapping. After mapping, empty, absolute,
drive-qualified, or parent-escaping paths suppress those source-derived actions.
Documentation and project issue links keep their own repository requirements.
Windows mappings use `/` separators. See [repository links](/docs/customize/repository/#imported-content).

## Documentation and compatibility {#compatibility}

The bilingual guides now describe the working 1.2.0 behavior: navigation and
translated-page SEO, source paths, search summaries, image precedence, diagram
endpoints, math, progressive enhancement, and publication safeguards. CSP
guidance accounts for inline scripts, styles, and style attributes. Interface
catalogs accept strings and supported plural-message maps. These documentation
corrections do not add a frontend dependency.

Hugo Extended **0.160.1** remains the compatibility floor. CI uses **0.165.0**,
and the module declares Go **1.27.0**. On Hugo 0.160.x, a non-default generic
`zh` alongside regional Chinese catalogs still needs `locale: zh-CN`.

Before adopting 1.2.0, compare copied navigation, Blog, image, math, and runtime
overrides with the updated theme. Correct malformed endpoint and resource
metadata before a warning-strict build. Review remote-resource requirements for
PDF output. Follow the [1.2 upgrade checklist](/docs/admin/upgrade/#preparing-1-2)
after the release tag is published and resolvable.

The [OINK CLI draft](/docs/cli/) introduces the separate optional `oink-cli`
project. It remains an unpublished `0.1.0-dev` candidate with its own version;
the theme and ordinary Hugo builds do not require it.

## Maintenance and publication tools {#maintenance-and-publication}

Snapshot tools reject destinations that overlap the site, selected theme,
running tools checkout, or another snapshot before cleanup. This includes
symlink aliases, retained `--keep` output, and RTL snapshot names. Selecting a
different theme does not remove protection from the running tools checkout.

`bin/book-pdf.py` restricts indirect network and navigation paths. Without
`--allow-remote-resources`, CSS- and SVG-initiated media requests are confined to
the local publication origin and data URLs. A CSP sandbox disables scripts;
meta-refresh navigation is rejected even with remote resources enabled.
Resource symlinks cannot escape the build tree. The opt-in permits passive
HTTP(S) media, not scripts or local-file access. Replacing output still needs
`--force`.

Migration tools preserve fenced examples nested in lists and blockquotes,
including literal quote and fence markers inside those examples. Unwrapping
supported legacy code blocks retains the surrounding list structure.

## Consumer upgrade workflow {#consumer-upgrades}

The new Python tool `bin/update-consumers.py` inventories immediate project
directories under selected roots, or explicitly selected sites. Inventory is
read-only by default. `--write` updates module files; `--check` verifies the
exact module graph and runs a warning-strict build with both Go/Hugo workspaces
and environment module replacements disabled.

Discovery skips linked worktrees, hidden copies, and non-default branches.
Review skipped or blocked results, persistent replacements, and vendor content.
`--refresh-vendor` is explicit: a `go.mod` update alone does not refresh `_vendor/`.
Discovery failures do not abandon other sites. Failed module updates restore
the original module files; a failed build retains the new pin for diagnosis.
The tool does not commit, push, or deploy. See the
[consumer maintenance contract](/docs/design/migration/#updating-consumers).

## Verification and release status {#verification}

Validate the final working tree with the owning theme checkers, runtime tests,
and the documentation site's `make check` and `make browser`. Use strict
production builds for publication and report the actual Hugo version and
accessibility scan scope. Earlier dated acceptance results remain historical
evidence; they do not certify later edits.

Publishing the exact tag, resolving its public module archive, updating
consumer pins, and verifying hosted output remain separate release steps.
