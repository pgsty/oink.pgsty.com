OINK 1.6.0 移除了 Sass、Bootstrap 的 JavaScript bundle 与 Lunr，使任意 edition 的
Hugo（`0.169.0` 及以上，完整兼容 Hugo `0.170+`）无需任何外部编译器即可构建站点。
本地搜索改用单一的扫描式 BM25 引擎，支持无需空格的中日韩查询、参数级锚点定位与超
2 MiB 自动拆分索引；Markmap、ReDoc、Mermaid、KaTeX、DocSearch 等随包运行时全面升级；
新增组件与评论按需接近加载、单行顶栏自适应溢出菜单、非活动侧栏分支缓存与 WebP 博客
题图，并对全部 32 份原生语言包完成了校对与收紧。

> [!IMPORTANT] 留在 `v1` 模块路径上的明确破坏性变更
> OINK 1.6.0 继续保留 `github.com/pgsty/oink` 模块路径以减少现有站点的路径改动，
> 同时退役了三个 SCSS 钩子、将样式发布路径从 `/scss/` 迁至 `/css/`，并移除 Bootstrap JS
> 与 Lunr。升级已有站点前请先阅读[破坏性变更与升级步骤](#upgrade)。

## 纯 CSS 与 Hugo 0.170 兼容 {#plain-css}

Hugo 0.170 移除了 LibSass 与 Extended 版，已发布的 OINK 1.5.1 在 Hugo 0.170 上如果不额外
安装 Dart Sass 将无法构建。OINK 1.6.0 彻底移除 Sass：主题样式表改为 `assets/css/td/` 下的
118 个纯 CSS 分层文件，由 Hugo 按层叠顺序直接拼接，不再需要编译器，Git 中也不再保存生成
样式文件。生产产物 `main.css` 与最后一次 Sass 编译结果逐字节一致，普通站点构建只需要任意
edition 的 Hugo 二进制程序（采用 Hugo Modules 时另需 Go `1.27.4`）。

- 样式表发布路径统一迁至 `/css/`：`css/main.css`、`css/fontawesome.css` 与 `css/redoc.css`。
- 站点自有规则改用纯 CSS 写在 `assets/css/project.css` 与按路径排序的
  `assets/css/project/*.css`。`assets/scss/` 下的三个旧钩子（`_variables_project.scss`、
  `_variables_project_after_bs.scss`、`_styles_project.scss`）会被忽略，并由 `warnidf`
  在每次构建中各告警一次。
- 不加载 `main` 的站点自有外壳，可通过 `partial "css/bundle.html"` 按名取用 `chrome`、
  `landing`、`search` 或 `compare`。
- `bin/check-stylesheets.py` 校验分层清单、禁止布局调用样式编译器，并在空 `PATH` 环境下
  验证探针站点构建。

## 移除 Bootstrap JS 与 Lunr {#leaner-runtime}

OINK 1.6.0 移除 `bootstrap.bundle.js`、`@popperjs/core`、`lunr` 及未被页面加载的
`katex.min.js`。每页加载的核心脚本 `js/core.js` 压缩后从 92 KB 降至不足 9 KB，
`assets/js/third_party/` 目录随之删除。

- 页脚与手机抽屉中的版本菜单改为 `base.js` 控制的 CSS 定位弹层（`.td-version-menu__list`，
  支持方向键与 Escape 导航）；Landing `download` 渠道切换由 `landing.js` 直接驱动并派发
  `td:tab-shown` 事件。
- `assets/css/td/bootstrap/` 继续保留 Bootstrap 组件样式，深浅色模式属性 `data-bs-theme` 与
  `data-bs-theme-value` 保持不变。若站点自有模板或正文依赖 Bootstrap JS 组件或
  `window.lunr`，需由站点自行加载对应脚本。

## 扫描式 BM25 本地搜索 {#local-search}

本地搜索用单一的扫描式 BM25 引擎同时取代了 Lunr 与旧子串回退，不再在浏览器里临时构建倒排
索引，消除了大型文档站首次英文查询的卡顿，同时保持 `params.offline_search*` 配置完全兼容。

- **无需空格的中日韩与混合查询**：连续中日韩文字段按重叠二元组匹配，无需附带词典
  （`数据库连接池超时` 不加空格即可命中），中日韩与拉丁文字边界自动断开。
- **词边界、标识符与符号串**：普通单词按整词边界匹配（`port` 不再命中 `support`），支持
  ASCII 词的 Porter 词干、其他字母文字的前四字符词干、将相邻字母互换记为一次编辑的拼写回退，
  以及标识符与 `->>` 等多字符符号串的字面匹配。
- **超过 2 MiB 自动拆分**：不超过 2 MiB 的索引继续以单文件原样发布；超过 2 MiB 的 `content`
  索引自动在首批文件中保留导航元数据，把正文拆至 `offline-search-body.<lang>.json`。标题、
  小节、参数条目与关键词结果立即呈现；不超过 8 MiB 的正文自动后台加载，更大体积或开启
  `Save-Data` 时等读者点击「搜索正文」后再加载。
- **参数级搜索条目**：每个带锚点的参数（`{.fields}` 或 `fields`/`field`）自动带有
  `data-td-search-entry`，`field` 短代码新增可选的 `id` 参数以保留 `guc-work-mem` 等既有锚点；
  搜索参数名可直接跳转到对应定义。

## 运行时升级与按需加载 {#runtimes}

`VENDOR.json`（现收录 25 项顶层依赖）全面更新随包运行时：DocSearch `5.2.0`、Mermaid `12.3.0`
（显式保留 `dagre` / `default` / `classic` 默认值）、KaTeX `0.19.1`（只发布 20 个 `woff2` 字体，
公式站产物从 1.1 MB 降至 0.3 MB）、Swagger UI `5.34.1`、Asciinema `3.18.0`、Infographic `0.2.20`、
Pako `3.0.3`、`idb-keyval` `6.3.0` 与 Viz.js `3.31.0`（内含 EPL-2.0 许可的 Graphviz `16.1.0`）。

- **Markmap 1.1.0**：以 `@markmap/*` 1.1.0 本地 ESM 模块与按需 MathJax 替换旧版 0.18 自动加载器、
  独立 D3、highlight.js 与 WebFontLoader。段落、代码块与表格转为节点注释，支持完整键盘交互、
  外观实时同步与源码回退；配置键改为 `foldLevel`、`wrapWidth`、`levelGap`、`siblingGap` 与
  `colorDepth`（旧键名会告警并被忽略）。
- **ReDoc 3.1.0**：每份 API 规范运行在独立的本地 HTML 文档与 hash 路由中，默认关闭遥测，
  多个实例不再干扰文章锚点或彼此导航。
- **按需接近加载**：Asciinema、ECharts、Infographic、Markmap 与 Giscus 改为在读者滚动接近时加载
  （Giscus 对 `loading: eager` 与 GitHub 登录回跳仍立即加载），避免重型引擎阻塞首屏，并在浏览器
  打印与加载失败时保留可读链接或源码。

## 外壳、32 语言本地化与出版加固 {#shell-i18n}

- **单行顶栏自适应溢出**：当品牌、桌面侧栏与右侧工具区挤窄水平空间时，带图标的顶栏项先缩略为
  图标模式（`params.icon: false` 或 `"none"` 可退出图标缩略），仍放不下的末尾项收拢到 `…` 展开
  面板（`ui_nav_more`）并保留完整图标、标签与子菜单。
- **更快的构建与更轻的图片**：未达 `sidebar_cache_limit` 时，当前页不在其中的侧栏分支每次构建只
  渲染一次且输出逐字节一致；博客 `banner`、`hero`、`wash` 题图重编码为 WebP 并附加
  `fetchpriority="high"`；分类法术语页缩略图按框裁切并懒加载。
- **32 份原生语言包校对**：审校全部 32 份界面目录（`i18n/*.yaml`，242 键），修正 `ar` / `fa`
  连写脚本的正值字距，合理加宽外观面板与页面操作菜单（在 200% 缩放下不超出视口），并让 6 份
  Giscus 预设样式表完全自包含。
- **Print、Book 与缓存加固**：补齐首页、落地页、分区与单页专用 Print 布局及共享的
  `print/page-id.html` 锚点工具；为页面级 `partialCached` 补全 baseURL 与语言键；加固 Book 编号、
  Markdown 目录转义及跨格式 `book-*` 索引一致性，并修正 Duo View、图表与命令面板的多处边界问题。

## 破坏性变更与升级步骤 {#upgrade}

固定 `v1.6.0` 前，请先对照[升级到 1.6.0](/zh/docs/admin/upgrade/#preparing-1-6)清单逐项核对：

1. 将 Go 升级至 **1.27.4+**，Hugo 升级至 **0.169.0+**（不限 edition，已在 **Hugo 0.170.1** 验证）。
2. 将 `assets/scss/_*_project*.scss` 钩子改写为纯 CSS 迁入 `assets/css/project.css`，把写死的
   `/scss/*.css` 路径改为 `/css/*.css`，自定义外壳改用 `partial "css/bundle.html"`
   （见[已退役的 SCSS 钩子](/zh/docs/admin/upgrade/#sass-hooks)）。
3. 清理站点对主题提供 `window.bootstrap`、`data-bs-toggle` 或 `window.lunr` 的依赖；Landing
   渠道切换事件从 `shown.bs.tab` 改为 `td:tab-shown`，版本列表 `.dropdown-menu` 选择器改为
   `.td-version-menu__list`（见 [Bootstrap JS](/zh/docs/admin/upgrade/#bootstrap-script)、
   [本地搜索](/zh/docs/admin/upgrade/#search-engine)）。
4. 迁移 Markmap 0.18 旧 YAML 选项（见[Markmap 迁移说明](/zh/docs/components/markmap/#migration)），
   使用 ReDoc 3 时在 CSP 中放行 `frame-src 'self'`，并在浏览器测试中先将懒加载组件滚入视口。

`v1.6.0` 标签发布后，固定模块版本并验证构建：

```sh
hugo mod get github.com/pgsty/oink@v1.6.0
hugo mod tidy
hugo --environment production --minify --printPathWarnings
```

提交更新后的 `go.mod` 与 `go.sum`（含 `go 1.27.4` 指令）。保持构建告警可见，切勿启用
`--panicOnWarning` 或 `HUGO_PANICONWARNING`。
