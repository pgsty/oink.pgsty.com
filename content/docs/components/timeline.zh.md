时间轴（Timeline）把事件排在一条竖直的轴线上，每个事件旁边是它的标记。标记就是给事件排序的东西：日期、时刻、版本号，或者「第 2 天」。写一个 Markdown 定义列表，每个术语是一个标记，每条定义是一个事件，再在列表下一行写 `{.timeline}`。主题只添加 CSS。

时间轴适用于项目里程碑、故障经过、产品历史和会议议程。读者要照着执行的操作流程用[步骤](/zh/docs/components/steps/)；每一项都需要在目录里占一个标题时，用[更新](/zh/docs/components/update/)条目。

## 最简例子 {#minimal}

标记独占一行，事件写在下一行的 `: ` 之后，条目之间空一行。`{.timeline}` 紧贴在最后一个事件下面。

```markdown {title="源码"}
2026-08-29
: **OINK 1.0.0。** 组件、配置与输出契约宣告稳定。

2026-10-15
: **OINK 1.3.0。** 新增 `type: expo` 图片相册。

2026-11-23
: **OINK 1.6.0。** 样式表改为纯 CSS，站点构建只需要 Hugo 可执行文件。
{.timeline}
```

2026-08-29
: **OINK 1.0.0。** 组件、配置与输出契约宣告稳定。

2026-10-15
: **OINK 1.3.0。** 新增 `type: expo` 图片相册。

2026-11-23
: **OINK 1.6.0。** 样式表改为纯 CSS，站点构建只需要 Hugo 可执行文件。
{.timeline}

`{.timeline}` 必须紧贴最后一个事件。中间多一个空行，Goldmark 就会悄悄丢掉这行属性，不给任何告警，列表按普通定义列表渲染。条目之间的空行则不能省：少了它，下一个标记会变成上一个事件正文里的一行字。

## 标记 {#markers}

标记是一行自由文本。主题不解析它，所以 `2026-11`、`09:02`、`v1.6.0`、`第 2 天`、`2026 Q3 – 2027 Q1` 都合法，事件按书写顺序排列。建议写纯文本：标记用小号半粗字体排版，数字等宽，时刻与日期上下对齐。

```markdown {title="源码"}
09:02 UTC
: **告警。** 生产分支上的部署工作流失败。

09:14 UTC
: **定位原因。** 新页面链接到一个已经改名的标题，链接检查中止了构建。

09:40 – 10:15 UTC
: **修复。** 更正链接，站点重新构建。

10:30 UTC
: **恢复。** 生产环境上线新页面。
{.timeline}
```

09:02 UTC
: **告警。** 生产分支上的部署工作流失败。

宽屏下标记列随最长的标记变宽，上限 10rem；更长的标记在列内换行。紧挨在 `: ` 行上方的每一行都是一个独立的标记，所以一个标记不能在源码里续写到第二行。

## 事件内容 {#events}

事件就是定义，可以包含块级内容：续行段落、列表和代码围栏。与任何定义列表一样，这些内容缩进两个空格，对齐到 `: ` 之后的那一列。事件开头的一段粗体是约定俗成的标题，只是写作习惯而不是语法，主题把它当普通粗体显示。

````markdown {title="源码"}
2026-11-23
: **OINK 1.6.0。** 样式表改为纯 CSS 层，三个 SCSS 钩子同时退役。

  用过这些钩子的站点分两步升级：

  - 把站点规则移到 `assets/css/project.css`；
  - 把改动过的每个 Sass 变量改写成它所生成的自定义属性。

  ```bash
  hugo mod get github.com/pgsty/oink@v1.6.0
  ```

未发布
: **时间轴与更新。** 分别用于带日期的事件和更新日志条目的原生组件。
{.timeline}
````

轴线画在每个事件的起始边上，事件内容再长，轴线也连续不断。

## 一个标记下的多个事件 {#several}

一个标记下写多行 `: `，就是共用这个标记的几个事件。它们在轴线上依次排开，共用一个节点。

```markdown {title="源码"}
2026-10-18
: **OINK 1.3.1。** 可读性修复，以及可选的文件树注释布局。
: **OINK 1.3.2。** 当天的补丁版本恢复了被 1.3.1 打破的仅依赖 Hugo 的构建。

2026-11-04
: **OINK 1.5.0。** 双语视图把页面和它的译文并排打开。
{.timeline}
```

## 何时用时间轴 {#which}

| 内容 | 用法 |
| --- | --- |
| 正文里带日期或有先后的事件 | 定义列表 + `{.timeline}` |
| 读者要照着执行的操作流程 | [步骤](/zh/docs/components/steps/) |
| 每一条都要在目录里有标题的更新日志条目 | [更新](/zh/docs/components/update/) |
| 带工期与依赖关系的排期 | [Mermaid](/zh/docs/components/mermaid/#gantt) 甘特图 |

## 呈现方式 {#rendering}

| 条件 | 布局 |
| --- | --- |
| 视口宽度 576px 及以上 | 两列：标记靠轴线一侧对齐，事件在它旁边；标记列按内容取宽，上限 10rem |
| 更窄的视口 | 单列：标记在事件上方，轴线与节点位于起始边 |
| Ink 与 Terminal 预设 | 节点是方形而不是圆形 |
| 强制颜色模式 | 轴线与节点使用系统文字颜色 |
| 从右到左书写的页面 | 轴线移到右侧，逻辑属性让整个布局镜像 |

样式的作用域是 `.td-content dl.timeline`。不带 `{.timeline}` 的定义列表照旧渲染；站点在正文以外已经命名为 `.timeline` 的元素也不受影响。

## 前置配置 {#prerequisites}

定义列表是 Goldmark 的扩展，Hugo 默认启用。属性行依赖 Goldmark 的块级属性，这是所有组件共用的[站点前置配置](/zh/docs/components/#prerequisites)之一。

```yaml {title="hugo.yml"}
markup:
  goldmark:
    extensions:
      definitionList: true # Hugo 的默认值
    parser:
      attribute:
        block: true # 启用 {…} 属性行
```

关闭定义列表后，每个标记和它的事件会合成一个段落，冒号按字面显示。

## 输出形态 {#outputs}

| 输出 | 呈现 |
| --- | --- |
| HTML | Goldmark 生成的 `<dl class="timeline">`：每个标记一个 `<dt>`，每个事件一个 `<dd>`；轴线与节点由 CSS 绘制 |
| 打印 | 同样的 HTML 结构；打印样式让标记与它的事件留在同一页 |
| Markdown 与 LLMS | 原样输出作者写的定义列表和 `{.timeline}` 行 |
| RSS | 渲染后的 `<dl>`；阅读器把标记和事件显示为术语与定义 |

时间轴不加载 JavaScript。读屏器按源码顺序把每个标记和事件读作术语及其定义；轴线与节点只是装饰。

## 参数参考 {#reference}

定义列表语法：

| 元素 | 必填 | 说明 |
| --- | --- | --- |
| 标记行 | 是 | 一行自由文本，建议纯文本。紧挨在 `: ` 行上方的每一行都是独立的标记 |
| `: 事件` | 是 | 每个标记至少一条。续行内容缩进两个空格 |
| 更多 `: ` 行 | 否 | 同一标记下的更多事件，共用一个节点 |
| 空行 | 是 | 写在条目之间；缺了它，下一个标记会并入上一个事件的正文 |
| `{.timeline}` | 是 | 紧贴最后一个事件的下一行，前面不能有空行 |
{.fields}

时间轴没有任何属性：没有图标、颜色、徽章、链接，也没有紧凑变体。写在同一行的 `id` 或其他 class（例如 `{#history .timeline}`）由 Goldmark 原样加到 `<dl>` 上。

## 限制与常见问题 {#limits}

- 事件不接受图标、颜色、徽章或链接参数。需要时把链接或[徽章](/zh/docs/components/badge/)写进事件正文。
- `{.timeline}` 前面多一个空行，这个作者标记就会被静默丢弃。所有 Goldmark 块级属性都是如此：属性根本到不了主题，所以无从告警。
- GitHub 和部分编辑器不渲染定义列表。源码依然读得通：一行标记，下面跟着若干 `: 事件` 行。
- 连写两行标记，第一个标记就没有事件，宽屏下轴线会断开一截。每个标记至少写一个事件。
- 不解析、不排序、不按年份分组：事件按源码顺序排列，标记也不做本地化。
- 事件不是标题，不进目录。需要进目录时改用[更新](/zh/docs/components/update/)标题。
