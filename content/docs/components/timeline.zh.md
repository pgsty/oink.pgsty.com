时间轴（Timeline）把事件排在一条竖直的轴线上，每个事件旁边是它的标记：日期、时刻、版本号、「第 2 天」，只要能给事件排序就行。项目里程碑、一次故障的经过、产品历史、会议议程都适合用它；它与步骤、更新条目和甘特图的区别见[何时用时间轴](#which)。

写法就是一个普通的 Markdown 定义列表：每个术语是一个标记，每条定义是一个事件，再在列表下一行写 `{.timeline}`。主题只添加 CSS，源码仍是普通 Markdown，页面也不加载脚本。

## 最简例子 {#minimal}

标记独占一行，事件写在下一行的 `: ` 之后，条目之间空一行。`{.timeline}` 紧贴在最后一个事件下面。

```markdown {title="源码"}
2024-03-12
: **v1.0**：首个稳定版本，支持在 EL 9 与 Ubuntu 24.04 上单节点安装。

2024-11-05
: **v2.0**：流复制从库与自动故障切换。

2025-09-30
: **v3.0**：PostgreSQL 18 成为默认版本。
{.timeline}
```

2024-03-12
: **v1.0**：首个稳定版本，支持在 EL 9 与 Ubuntu 24.04 上单节点安装。

2024-11-05
: **v2.0**：流复制从库与自动故障切换。

2025-09-30
: **v3.0**：PostgreSQL 18 成为默认版本。
{.timeline}

两处换行都有讲究。`{.timeline}` 必须紧贴最后一个事件：中间隔一个空行，Goldmark 在主题看到之前就把这行属性丢掉了，因此不会有任何告警，列表按普通定义列表渲染。条目之间的空行同样不能省，少了它，下一个标记会变成上一个事件正文里的一行字。

## 标记 {#markers}

标记是一行自由文本。主题不解析它，所以 `2026-11`、`09:02`、`v1.6.0`、`第 2 天`、`2026 Q3 – 2027 Q1` 都可以，事件按书写顺序排列。标记用小号半粗字体排版，数字等宽，时刻与日期上下对齐；写成纯文本效果最好。

```markdown {title="源码"}
09:02 UTC
: **告警**：生产分支上的部署工作流失败。

09:14 UTC
: **定位原因**：新页面链接到一个已经改名的标题，链接检查中止了构建。

09:40 – 10:15 UTC
: **修复**：更正链接，站点重新构建。

10:30 UTC
: **恢复**：生产环境上线新页面。
{.timeline}
```

09:02 UTC
: **告警**：生产分支上的部署工作流失败。

09:14 UTC
: **定位原因**：新页面链接到一个已经改名的标题，链接检查中止了构建。

{.timeline}

宽屏下标记列随最长的标记变宽，上限 10rem，更长的标记在列内换行。一个标记不能在源码里续写到第二行：紧挨在 `: ` 行上方的每一行都是独立的标记，连写两行标记，第一个就没有事件，轴线上会空出一截。

## 事件内容 {#events}

事件就是定义，可以包含续行段落、列表和代码围栏，这些内容缩进两个空格，对齐到 `: ` 之后的那一列。事件开头的一段粗体是常用的标题写法，只是写作习惯，主题把它当普通粗体显示。

````markdown {title="源码"}
2025-09-30
: **v3.0**：PostgreSQL 18 成为默认版本，PostgreSQL 13 退出支持列表。

  仍在 PostgreSQL 13 上的集群分两步升级：

  - 先做一次新的基础备份；
  - 在主库上执行 `pg_upgrade`，再从主库重建各个从库。

  ```bash
  pg_upgrade -b /usr/pgsql-13/bin -B /usr/pgsql-18/bin -d /var/lib/pgsql/13/data -D /var/lib/pgsql/18/data --link
  ```

下一版本
: **逻辑复制**：一条命令在集群之间建立发布与订阅。
{.timeline}
````

2025-09-30
: **v3.0**：PostgreSQL 18 成为默认版本，PostgreSQL 13 退出支持列表。

  仍在 PostgreSQL 13 上的集群分两步升级：

  - 先做一次新的基础备份；
  - 在主库上执行 `pg_upgrade`，再从主库重建各个从库。

  ```bash
  pg_upgrade -b /usr/pgsql-13/bin -B /usr/pgsql-18/bin -d /var/lib/pgsql/13/data -D /var/lib/pgsql/18/data --link
  ```

{.timeline}

轴线画在每个事件的起始边上，事件内容再长，轴线也连续不断。

## 一个标记下的多个事件 {#several}

一个标记下写多行 `: `，就是共用这个标记的几个事件，它们在轴线上依次排开，共用一个节点。

```markdown {title="源码"}
2025-10-14
: **v3.0.1**：修复从库超过三个的集群上故障切换超时的问题。
: **v3.0.2**：当天的补丁版本恢复了被 3.0.1 破坏的隔离网络安装。

2025-12-02
: **v3.1**：在命令行完成时间点恢复（PITR）。
{.timeline}
```

## 何时用时间轴 {#which}

| 内容 | 用法 |
| --- | --- |
| 正文里带日期或有先后的事件 | 定义列表 + `{.timeline}` |
| 读者要照着执行的操作流程 | [步骤](/zh/docs/components/steps/) |
| 每一条都要在目录里有标题的更新日志条目 | [更新](/zh/docs/components/update/) |
| 带工期与依赖关系的排期 | [Mermaid](/zh/docs/components/mermaid/#gantt) 甘特图 |

## 呈现方式 {#rendering}

| 条件 | 布局 |
| --- | --- |
| 视口宽度 576px 及以上 | 两列：标记靠轴线一侧对齐，事件在它旁边；标记列按内容取宽，上限 10rem |
| 更窄的视口 | 单列：标记在事件上方，轴线与节点位于起始边 |
| Ink 与 Terminal 预设 | 节点是方形而不是圆形 |
| 强制颜色模式 | 轴线与节点使用系统文字颜色 |
| 从右到左书写的页面 | 轴线移到右侧，整个布局镜像 |

样式只作用于文章正文里的 `dl.timeline`。没有这个标记的定义列表，以及站点在正文以外已经命名为 `.timeline` 的元素，都不受影响。

## 前置配置 {#prerequisites}

定义列表是 Goldmark 的扩展，Hugo 默认启用。属性行依赖 Goldmark 的块级属性，这是所有组件共用的[站点前置配置](/zh/docs/components/#prerequisites)之一。

```yaml {title="hugo.yml"}
markup:
  goldmark:
    extensions:
      definitionList: true # Hugo 的默认值
    parser:
      attribute:
        block: true # 启用 {…} 属性行
```

关闭定义列表后，每个标记和它的事件会合成一个段落，冒号按字面显示。

## 输出形态 {#outputs}

时间轴不加载 JavaScript。读屏器按源码顺序把每个标记和事件读作术语及其定义，轴线与节点只是装饰。打印时每个标记与它的事件留在同一页；Markdown 与 LLMS 输出原样保留定义列表和 `{.timeline}` 行；订阅阅读器里显示为普通的定义列表。

## 参数参考 {#reference}

定义列表语法：

| 元素 | 必填 | 说明 |
| --- | --- | --- |
| 标记行 | 是 | 一行自由文本，建议纯文本。紧挨在 `: ` 行上方的每一行都是独立的标记 |
| `: 事件` | 是 | 每个标记至少一条。续行内容缩进两个空格 |
| 更多 `: ` 行 | 否 | 同一标记下的更多事件，共用一个节点 |
| 空行 | 是 | 写在条目之间；缺了它，下一个标记会并入上一个事件的正文 |
| `{.timeline}` | 是 | 紧贴最后一个事件的下一行，前面不能有空行 |
{.fields}

时间轴本身没有属性：没有图标、颜色、徽章、链接，也没有紧凑变体。写在同一行的 `id` 或其他 class（例如 `{#history .timeline}`）由 Goldmark 原样加到 `<dl>` 上。

## 限制与常见问题 {#limits}

- 事件不接受图标、颜色、徽章或链接参数。需要时把链接或[徽章](/zh/docs/components/badge/)写进事件正文。
- GitHub 和部分编辑器不渲染定义列表，但源码依然读得通：一行标记，下面跟着若干 `: 事件` 行。
- 标记不解析、不排序、不分组，也不做本地化；事件按源码顺序排列。
- 事件不是标题，不进目录。需要进目录时改用[更新](/zh/docs/components/update/)标题。
