更新（Update）是一条更新日志条目：一个普通的 Markdown 标题，末尾加上 `{.update}`。每个条目上方多出一段间距和一条分隔线，一长串条目读起来更有节奏；可选的 `date` 与 `tags` 属性会在标题下方加一行元数据。单页更新日志、「新功能」页面、周报或政策变更记录都适合用它。

条目仍然是标题，所以标题有的它都有：目录条目、锚点、搜索小节和打印 ID。不加载脚本。每个版本都需要独立页面时，改用[发布页](#which)。

## 最简例子 {#minimal}

在标题末尾写 `{.update}`，`date` 和 `tags` 写在同一对花括号里。版本条目建议在最前面写上显式 `#id`：Goldmark 从标题文字生成锚点时会剥掉点号（`v1.6.0 — …` 会变成 `#v160--…`，`v1.10` 和 `v11.0` 还会碰撞），而 `{#v1-6-0 .update …}` 既干净又稳定，标题改了锚点也不变。

```markdown {title="源码"}
### v1.6.0 — 默认使用 PostgreSQL 18 {#v1-6-0 .update date="2026-11-23" tags="破坏性变更, 性能"}

新建集群默认使用 PostgreSQL 18，并开启异步 I/O。
```

### v1.6.0 — 默认使用 PostgreSQL 18 {#v1-6-0 .update date="2026-11-23" tags="破坏性变更, 性能"}

新建集群默认使用 PostgreSQL 18，并开启异步 I/O。

更新日志页通常每个条目用 `##`。这里的示例用 `###`，好让它们在目录里嵌套在本页自己的小节之下。

## 日期 {#date}

`date` 可以精确到年、月或日（`YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`）。它渲染为 `<time datetime="…">`，并按原样显示，`2026-11` 就显示为 `2026-11`。

```markdown
## 2026 年回顾 {.update date="2026"}
## 11 月札记 {.update date="2026-11"}
## v1.6.0 {.update date="2026-11-23"}
```

其他取值——包括不存在的日历日期（如 `2026-02-30` 或 `2025-02-29`）、带时刻或时区的时间戳，以及没加引号的数字 `date=2026`——都会告警并给出标题和页面，日期被丢弃，标题、其余合法的 `tags` 与条目正文保留。闰日如 `2024-02-29` 可以通过。

不加引号的完整日期（如 `{.update date=2026-11-01}`）后果更重：Goldmark 无法解析它，会丢弃整个属性块，把它原样留在标题文字里。只要标题末尾留着一个未被解析、含 `.update` 的 `{…}` 块，无论前面有没有 `#id`（如 `{.update date=2026-11-01}` 或 `{#v1-6-0 .update date=2026-11-01}`），构建都会告警。每个值都要加引号。

## 标签 {#tags}

`tags` 是逗号分隔的纯文本字符串（英文 `,` 与中文全角 `，` 都作为分隔符）。每一项去掉首尾空白，空项跳过，所以 `tags=" 修复 ,, 文档 "` 得到「修复」「文档」两个 chip。非字符串值（例如没加引号的 `tags=true`）会告警并被丢弃。无论写什么，chip 的样子都一样，颜色由预设决定；标签里的 Markdown 按字面显示。

这些不是 Hugo 分类法里的 tags：不生成词条页，也不链接到任何地方。主题不会翻译它们，请用页面的语言来写。

## 不带元数据的条目 {#no-metadata}

两个属性都可以省略。`## 未发布 {.update}` 是合法条目，有条目的间距和分隔线，但没有元数据行；没有日期、`tags` 里又只有逗号和空格时，同样不输出元数据行。

条目下的正文是普通 Markdown。条目里更低一级的标题就是普通标题，在目录里嵌套在条目之下，不需要标记。

## 它仍是标题 {#heading}

标记不改变标题原有的任何行为：

- 目录只显示标题文字，不显示日期和标签。
- 锚点和悬停时出现的自链接照常可用。
- [键盘导航](/zh/docs/customize/keyboard/#reading)中的 <kbd>J</kbd> 与 <kbd>K</kbd> 会在每个条目上停下。
- 本地搜索把条目索引为一个以标题文字命名的小节；当 `offline_search_index` 为 `content`（主题默认值）时，日期和标签会以分隔开的词项计入该小节的正文。
- 多页打印像对待其他标题一样，给条目的 ID 加上命名空间。

元数据行跟在标题之后，而不是写进标题里，因此标题文字、它的无障碍名称和搜索标题都与源码一致。没有显式 `#id` 时，锚点由标题文字生成（点号会被移除，长标题会变成冗长的 slug），条目改名后链接也会跟着变，所以版本条目以及会被其他页面链接的条目，都建议写上 `#id`。

## 单页更新日志 {#demo}

一串从新到旧排列的条目。下面三个条目和一个子小节都出现在目录里本节之下。

```markdown {title="源码"}
### 未发布 {#demo-unreleased .update}

一条命令即可在两个集群之间建立逻辑复制。

### v1.6.0 {#demo-v1-6-0 .update date="2026-11-23" tags="破坏性变更"}

新建集群默认使用 PostgreSQL 18。

#### 升级须知 {#demo-v1-6-0-upgrade}

- 想继续创建 PostgreSQL 17 集群，在清单里设置 `pg_version: 17`。
- 把 `pg_backup_dir` 改名为 `backup_dir`。

### v1.5.1 {#demo-v1-5-1 .update date="2026-11" tags="变更, 修复"}

从库超过三个的集群上，故障切换不再超时。
```

### 未发布 {#demo-unreleased .update}

### v1.6.0 {#demo-v1-6-0 .update date="2026-11-23" tags="破坏性变更"}

## 更新还是发布页 {#which}

| 需求 | 用法 |
| --- | --- |
| 同一页上一条可读的条目流 | `.update` 标题 |
| 每个版本一页，有自己的 URL、订阅条目、发布资产或 GitHub Release | 由 `layout: releases` 汇总的[发布页](/zh/docs/write/releases/#release-index) |
| 夹在其他正文里的一小段日期序列 | [时间轴](/zh/docs/components/timeline/) |

同一套产品的发布说明应只选一种作为单一事实来源——要么集中在单个 `.update` 更新日志页，要么按版本分立并由 `layout: releases` 汇总——不要在两处重复维护同一版本。如果单独的「新功能」页需要提及已有发布页的里程碑，直接链接过去，不要把发布说明再写一遍。

## 输出形态 {#outputs}

更新不加载 JavaScript。HTML 中标题带上 `class="update"`，后面跟一个 `<div class="td-update-meta">`，里面是 `<time datetime>` 和每个标签一个 `<span class="td-update-tag">`。各项之间有一个屏幕上不占位置的逗号，所以复制出的文字、本地搜索和订阅阅读器拿到的是 `2026-11-23, 破坏性变更, 性能`，而不是 `2026-11-23破坏性变更性能`。打印时无论屏幕是浅色还是深色模式，都使用浅色纸张配色，并让标题与它的元数据行留在同一页。Markdown 与 LLMS 输出原样保留带属性块的标题行（GitHub 等原始 Markdown 查看器会把 `{…}` 原样显示出来）。整页仍然只有一个 URL，条目不会成为单独的订阅条目。

## 参数参考 {#reference}

标题末尾的属性块：

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `.update` | 标记 | — | 让标题成为条目；任意级别，通常用 `##` |
| `date` | 字符串（`YYYY`、`YYYY-MM` 或合法日历 `YYYY-MM-DD`） | — | 渲染为 `<time datetime>` 并按原样显示；非字符串与无效日期告警并丢弃 |
| `tags` | 字符串（`,` 或 `，` 分隔的纯文本） | — | 每个非空项一个中性 chip，去掉首尾空白；非字符串告警并丢弃 |
| `id` | 锚点 | 由标题文字生成 | 版本条目建议显式填写，写在最前：`{#v1-6-0 .update …}` |
{.fields meta="type default"}

`date` 和 `tags` 只在与 `.update` 同时出现时生效；写在其他标题上，它们按未知属性告警并被丢弃。

## 限制与常见问题 {#limits}

- 没有吸顶的标签栏，也没有双栏布局；右侧目录已经在跟踪各个条目。
- 条目没有自己的 URL 或订阅条目。每个版本都需要时，改用[发布页](/zh/docs/write/releases/)。
- 目录只显示标题文字。希望读者在目录里看到日期，就把日期写进标题文字。
- 标签不翻译、不着色、不链接。
- 条目按源码顺序排列，不排序、不筛选，也不能从数据生成。
