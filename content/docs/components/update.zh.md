更新（Update）是一条更新日志条目：一个普通的 Markdown 标题，末尾加上 `{.update}` 作者标记。可选的 `date` 与 `tags` 属性会在标题下方加一行元数据：机器可读的日期，以及中性的标签 chip。每个条目标题上方还会多出一段间距和一条分隔线，让一长串条目读起来有节奏。条目依然是标题，因此目录条目、锚点、搜索小节和打印 ID 都保持不变。不加载脚本。

更新适用于单页更新日志、「新功能」页面、周报或政策变更记录。每个版本都需要独立页面时，改用[发布页](#which)。

## 最简例子 {#minimal}

在标题末尾写 `{.update}`，`date` 和 `tags` 写在同一对花括号里。写在最前面的 `#id` 可以省略，它给条目一个简短的锚点，标题改了锚点也不变。更新日志页通常每个条目用 `##`；本页的示例用 `###`，好让它们在右侧目录里嵌套在所属小节之下。

```markdown {title="源码"}
### v1.6.0 — 纯 CSS 样式表 {#v1-6-0 .update date="2026-11-23" tags="破坏性变更, 性能"}

样式表现在由纯 CSS 层组成，站点构建只需要 Hugo 可执行文件。
```

### v1.6.0 — 纯 CSS 样式表 {#v1-6-0 .update date="2026-11-23" tags="破坏性变更, 性能"}

样式表现在由纯 CSS 层组成，站点构建只需要 Hugo 可执行文件。

## 日期 {#date}

`date` 可以精确到年、月或日：`YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。它渲染为 `<time datetime="…">`，并按原样显示，`2026-11` 就显示为 `2026-11`。

```markdown
## 2026 年回顾 {.update date="2026"}
## 11 月札记 {.update date="2026-11"}
## v1.6.0 {.update date="2026-11-23"}
```

其他取值会告警，告警里给出标题和页面路径，然后丢弃日期；标题和条目的其余内容保留。检查只看格式，不查日历：月份须在 01–12 之间，日须在 01–31 之间，所以 `2026-02-30` 也能通过。不接受时刻和时区。

## 标签 {#tags}

`tags` 是逗号分隔的纯文本列表。每一项去掉首尾空白，空项跳过，所以 `tags=" 修复 ,, 文档 "` 得到「修复」「文档」两个 chip。chip 是中性的：无论写什么，样子都一样，颜色由预设决定。标签里的 Markdown 按字面显示。

这些不是 Hugo 分类法里的 tags：不生成词条页，也不链接到任何地方。标签用页面的语言来写，主题不会翻译它们。

## 不带元数据的条目 {#no-metadata}

两个属性都可以省略。`## 未发布 {.update}` 是合法条目：有条目的间距和分隔线，但没有元数据行。没有日期、`tags` 里又只有逗号和空格时，同样不输出元数据行。

条目下的正文是普通 Markdown。条目里更低一级的标题就是普通标题：在目录里嵌套在条目之下，不需要标记。

## 它仍是标题 {#heading}

标记不改变标题原有的任何行为：

- 目录只显示标题文字，不显示日期和标签。
- 锚点和悬停时出现的自链接照常可用。
- [键盘导航](/zh/docs/customize/keyboard/#reading)中的 <kbd>J</kbd> 与 <kbd>K</kbd> 会在每个条目上停下。
- 本地搜索把条目索引为一个以标题文字命名的小节，日期和标签算作这个小节的正文。
- 多页打印像对待其他标题一样，给条目的 ID 加上命名空间。

元数据行跟在标题之后，而不是写进标题里，因此标题文字、它的无障碍名称和搜索标题都与源码一致。没有显式 `#id` 时，锚点由标题文字生成，条目改名后链接也会跟着变。其他页面要链接某个条目时，给它写上 `#id`。

在不带 `.update` 的标题上写 `date` 和 `tags`，它们就是未知属性：会告警并被丢弃。

## 单页更新日志 {#demo}

一串从新到旧排列的条目。下面三个条目和一个子小节都出现在本页右侧的目录里，位于本节之下。

## 更新还是发布页 {#which}

| 需求 | 用法 |
| --- | --- |
| 同一页上一条可读的条目流 | `.update` 标题 |
| 每个版本一页，有自己的 URL、订阅条目、发布资产或 GitHub Release | 由 `layout: releases` 汇总的[发布页](/zh/docs/write/releases/#release-index) |
| 夹在其他正文里的一小段日期序列 | [时间轴](/zh/docs/components/timeline/) |

已经有发布页的版本，不必在更新流里再描述一遍，在条目里链接到发布页即可。

## 输出形态 {#outputs}

| 输出 | 呈现 |
| --- | --- |
| HTML | 带 `class="update"` 的标题，后跟 `<div class="td-update-meta">`，里面是 `<time datetime>` 和每个标签一个 `<span class="td-update-tag">` |
| 打印 | 同上；多页打印给标题 ID 加命名空间，打印样式让标题与元数据行不分开 |
| Markdown 与 LLMS | 原样输出作者写的标题行，包括属性块 |
| RSS | 标题与元数据行，均为静态 HTML |

更新不加载 JavaScript。整页仍然只有一个 URL，条目不会成为单独的订阅条目。

## 参数参考 {#reference}

标题末尾的属性块：

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `.update` | 标记 | — | 让标题成为条目；任意级别，通常用 `##` |
| `date` | `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD` | — | 渲染为 `<time datetime>` 并按原样显示；其他取值告警并丢弃 |
| `tags` | 逗号分隔的纯文本 | — | 每个非空项一个中性 chip，去掉首尾空白 |
| `id` | 锚点 | 由标题文字生成 | 与普通标题相同，写在最前：`{#v1-6-0 .update …}` |
{.fields meta="type default"}

`date` 和 `tags` 只在与 `.update` 同时出现时生效；没有标记时，它们按未知属性告警并被丢弃。

## 限制与常见问题 {#limits}

- 没有吸顶的标签栏，也没有双栏布局。右侧目录已经在跟踪各个条目。
- 条目没有自己的 URL 或订阅条目。每个版本都需要时，改用[发布页](/zh/docs/write/releases/)。
- 目录只显示标题文字。希望读者在目录里看到日期时，把日期写进标题文字。
- 标签不翻译、不着色、不链接。
- 条目按源码顺序排列，不排序、不筛选，也不能从数据生成。
- 日期只按格式检查，不对照日历。
