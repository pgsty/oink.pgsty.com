OINK 直接沿用 Hugo 的多语言模型：在 `hugo.yml` 里写一个 `languages` 块，译文与原文放在同一目录，用文件名后缀区分语言。增加一种语言要动五个地方：配置、译文、菜单、首页数据，以及（只在想改措辞时才需要的）主题界面文案。语言选择器、`hreflang` 链接与分语言搜索都随之自动生效，不需要另外设置。

## 启用第二种语言 {#enable}

```yaml {title="hugo.yml"}
defaultContentLanguage: en

languages:
  en:
    label: English
    locale: en-US
    weight: 1
    title: Acme DB Docs
    params:
      description: Documentation for the Acme DB time-series database
  zh:
    label: 简体中文
    locale: zh-CN
    weight: 2
    title: Acme DB 文档
    params:
      description: Acme DB 时序数据库文档
      time_format_default: 2006年1月2日
      time_format_blog: 2006年1月2日
```

- `label` 是语言选择器里显示的名字，用该语言自己的文字书写：写 `简体中文`，而不是 `Chinese`。
- `locale` 是标准语言标签，用于 `<html lang>`、`hreflang` 备用链接与 Open Graph 元数据。
- `weight` 决定语言的排列顺序，小的在前，语言选择器及其一键轮换都按这个顺序。
- `params` 为该语言覆盖站点参数，这里没写的键沿用全局值。日期格式通常需要按语言分别设置。

默认语言不带路径前缀（英文在 `/docs/…`），其它语言各有自己的前缀（中文在 `/zh/docs/…`）。默认语言也要前缀时，加上 `defaultContentLanguageInSubdir: true`。已上线的站点这样改会改变所有 URL，需要同时配置重定向。

## 翻译页面 {#files}

译文放在原文旁边，在扩展名前加上语言代码。Hugo 把基础文件名相同的文件配成一对，下面就是同一页面的两个语言版本：

```filetree
- content/docs/
  - install.md          # 英文
  - install.zh.md       # 中文
  - _index.md
  - _index.zh.md
```

页面包同理：`index.md` 与 `index.zh.md` 放在同一个目录里。包内的资源，不带语言后缀的由所有语言共享，带后缀的只属于对应语言。引用带后缀的资源时写不带后缀的名字，例如 `![截图](screenshot.webp)`，Hugo 会为当前语言选出对应文件：

```filetree
- content/docs/install/
  - index.md              # 英文页
  - index.zh.md           # 中文页
  - topology.webp         # 两种语言共用
  - screenshot.zh.webp    # 只有中文页使用
```

页面包里只有 `index.zh.md` 时，每个资源都要带 `.zh.` 后缀。不带后缀的资源归属默认语言，而默认语言在这个包里没有页面，中文页面就看不到它们。

读者看得到的内容要翻译，Hugo 用来组织结构的内容要保持一致：

- **翻译**：`title`、`description`、摘要、菜单标签、标签名、图片替代文字、提示块正文，以及短代码里面向读者的参数。
- **保持一致**：日期、`weight`、别名，以及其它影响路由或顺序的元数据；`weight` 不同，页面在两种语言的侧栏里就会排在不同位置。
- **不翻译**：命令、配置键、文件名、URL、版本号、产品名与短代码名。

## 菜单、首页与界面文案 {#per-language}

有三处内容不在 `content/` 里，需要每种语言各写一份。

**菜单** 写在各自的语言下：

```yaml {title="hugo.yml"}
languages:
  zh:
    menus:
      main:
        - identifier: docs
          name: 文档
          pageRef: /docs
          weight: 20
```

各语言要使用相同的 `identifier`，因为命令面板的快速链接和搜索结果的分组都按它匹配。菜单的完整写法见[导航与菜单](/zh/docs/customize/navigation/)。

**首页数据** 每种语言一个文件：`data/home/en.yaml`、`data/home/zh.yaml`；某种语言没有文件时回退到 `en.yaml`。见[首页与落地页](/zh/docs/customize/home/)。

**界面文案**（例如搜索框提示、页面操作按钮的文字）已经翻译好了：主题为 32 个 locale 提供完整的母语文案（`ar`、`az`、`bg`、`bn`、`de`、`en`、`es`、`et`、`fa`、`fi`、`fr`、`he`、`hi`、`hu`、`it`、`ja`、`ko`、`nl`、`no`、`oc`、`pl`、`pt-br`、`ro`、`ru`、`sr-cyrl`、`sr-latn`、`sv`、`tr`、`uk`、`zh`、`zh-cn`、`zh-tw`）。`zh` 与 `zh-cn` 是简体中文，`zh-tw` 是繁体中文。要改某条措辞，在站点自己的 `i18n/` 下建一个同名文件，只写要改的键；键名见主题的 `i18n/en.yaml`，原文里的 `{{ .Count }}` 之类占位符必须保留。

```yaml {title="i18n/zh.yaml"}
ui_search: 搜索文档
```

## 对齐标题锚点 {#anchors}

Hugo 根据标题文字生成 ID，译文标题因此得到不同的 ID：`/docs/install/#prerequisites` 与 `/zh/docs/install/#前置条件` 是同一节的两个锚点。从一种语言复制来的深链在另一种语言里失效，每条交叉引用都得写两遍，[双列视图](#bilingual-view)也无法让两侧停在同一节。所以要在译文标题上显式写出原文的 ID：

```markdown {title="install.zh.md"}
## 前置条件 {#prerequisites}
```

ID 要从英文页面渲染出的 HTML 里取，不要凭标题文字推测，因为标题里的行内代码、徽章或短代码都会改变生成的 ID。两边的标题数量、顺序与 ID 保持一致；只在一种语言里存在的小节，给它一个独立、稳定、不与对方冲突的 ID。写页面时顺手加上 `{#id}`，比事后补要省事得多。

构建之后，可以这样比对一对译文：

```bash
ids() { grep -oE '<h[2-6][^>]* id="?[^" >]+' "$1" | sed -E 's/.*id="?//'; }
diff <(ids public/docs/install/index.html) <(ids public/zh/docs/install/index.html)
```

要在 CI 里检查所有译文对，可以参考 OINK 文档站使用的 [`check-doc-translations.mjs`](https://github.com/pgsty/oink.pgsty.com/blob/main/scripts/check-doc-translations.mjs)，它比对源码结构与渲染后的标题 ID。这个脚本按该仓库的内容栏目与中英文文件命名编写，用到其它站点之前要先调整这两处。

## 缺译页面与语言选择器 {#fallback}

语言选择器的图标本身就是一个链接，指向按 `weight` 排序的下一种语言，到最后一种后回到第一种，所以双语站点点一下就能切换。悬停或键盘聚焦时展开列出全部语言的菜单；在触摸屏上，点按直接切换。

菜单始终列出所有已配置的语言。选中某种语言时，当前页有该语言译文就打开译文，没有就打开该语言的 **首页**。跳到首页总比 404 好，但读者未必察觉自己被带到了别处，所以要把“每个页面都有译文”当作需要检查的规则，而不是依赖这个回退。

> [!NOTE] 缺译不会用原文填充
> 某个页面没有中文版时，中文站里就没有这一页：侧栏、搜索索引与翻页顺序都不包含它。

搜索引擎只看到真实存在的译文：`hreflang` 只列出当前页与它的实际译文，不包括回退到首页的情况，见[规范链接与语言备用链接](/zh/docs/admin/analytics/#canonical-hreflang)。本地搜索同样按语言分开，在中文页面搜索只命中中文内容，支持不加空格的中文、中英混合查询与技术标识符，见[全文检索](/zh/docs/customize/search/)。

## 双列视图 {#bilingual-view}

双列视图让读者把页面与它的某个译文并排打开，适合核对译文，或者借助母语阅读第二语言。开启方式：

```yaml {title="hugo.yaml"}
params:
  ui:
    compare: true
```

Docs、Book 与博客页面在同一站点下有已发布的译文时，页面操作旁会出现「打开双列视图」按钮。读者也可以从命令面板执行「双列视图」，或在开启键盘导航时按 {{< kbd "B" >}}（可以直接在本页试试），再按一次 {{< kbd "B" >}} 返回。当前页面固定在阅读起始的一侧，另一侧窗格加载译文；页面有两种以上语言时，读者可以从工具栏菜单选择目标语言。宽度小于 `900px` 时，视图变成带语言切换栏的单窗格布局。

「同步滚动」开关按标题 ID 匹配章节，让两侧窗格停在同一节，这正是[对齐锚点](#anchors)的意义所在。部分标题没有对应项，或两页没有共同标题时，它会在匹配的标题之间或按整体阅读进度估算位置，开关旁的橙色「!」会说明是哪种情况，悬停、聚焦或轻触即可查看说明。标题 ID 重复，或在两种语言里顺序不同时，「同步滚动」会自动关闭，两侧窗格各自独立滚动。

双列视图不会让构建多出任何页面：只有读者打开它时，浏览器才在同源 frame 里加载已有的两篇 HTML 页面。没有译文的页面、草稿、回退到首页的情况，以及部署在其它域名上的译文，都会自动排除。要让某种语言完全不参与（既不作为正在阅读的页面，也不作为对照的译文），在 `languages.<lang>.params.ui` 下设置 `compare: false`。

在生产环境开启之前，先确认两点：

- 写在 `hooks/head-end.html` 里的统计脚本会在每个窗格内再执行一次，除非用 `window.OinkComparePane` 加以判断，见[分析与 SEO](/zh/docs/admin/analytics/#bilingual-view)。
- 内容安全策略（CSP）需要允许 `frame-src 'self'`，服务器也不能发送 `X-Frame-Options: DENY` 或 `frame-ancestors 'none'`，见[内容安全策略](/zh/docs/admin/deploy/#csp)。

## 从右向左的语言 {#rtl}

在语言下声明书写方向：

```yaml {title="hugo.yml"}
languages:
  ar:
    label: العربية
    locale: ar
    direction: rtl
    weight: 3
```

`<html dir>` 随之改变，主题还会加载 Bootstrap 的 RTL 样式表。主题自己的 CSS 使用逻辑属性（`margin-inline-start` 而不是 `margin-left`），布局会自动镜像。站点自己的 CSS 也要使用逻辑属性，否则在 RTL 下元素会落在错误的一侧。

## 验证 {#verify}

1. 在站点根目录构建，确认两种语言都有输出。下面的路径假设英文在 `/`、中文在 `/zh/`；检查索引只适用于开启了本地搜索的站点：

   ```bash
   hugo --printPathWarnings
   ls public/index.html public/zh/index.html
   ls public/offline-search-index.*
   ```

2. 对照 [SEO 行为](/zh/docs/admin/analytics/#canonical-hreflang)检查一个有译文页面的 `hreflang` 链接：只列出真实存在的译文，博客每个分页都有自己的 canonical，第一页之后的分页省略语言备用链接。

   ```bash
   # 换成你的站点实际生成的页面。
   PAGE=public/zh/docs/getting-started/index.html
   test -f "$PAGE" && grep -o '<link[^>]*hreflang[^>]*>' "$PAGE"
   ```

3. 在有译文的页面上用语言选择器切换语言，确认打开的是同一篇文档；在没有译文的页面上，确认打开的是另一种语言的首页，而不是 404。

4. 用两种语言分别搜索同一个概念，确认都有结果。

5. 按[对齐标题锚点](#anchors)中的方法比对一对译文的标题 ID。
