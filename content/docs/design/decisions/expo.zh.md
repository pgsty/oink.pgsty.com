## 背景 {#context}

Docs 组织说明，Blog 组织文章，Book 组织章节。Expo 按主题和相册组织图片收藏。
读者需要浏览相册、选择图片，并查看细节。

Graph 实验使用已有收藏的独立副本，包含 149 个相册、7,658 张原图。
其中有不同尺寸的图片、长图、GIF、说明和已有引用锚点。
这份收藏提供了最初的内容与规模需求。

## 选择 {#decisions}

### 每个相册对应一个页面包 {#one-bundle-per-album}

一个相册对应一个 Hugo 叶子页面包，包含 `index.md` 和图片文件。
文件名提供默认标题。可选的 `resources` 元数据补充说明、署名、顺序、显式 ID，
以及独立原图路径。

| 考虑过的模型 | 对创作的影响 |
| --- | --- |
| 每张图片一个目录和元数据文件 | 大型收藏需要管理大量小文件 |
| 每张图片一个 Markdown 页面 | 适合逐图撰写文章，但每张图片都需要页面模型 |
| 每个相册一个页面包，资源元数据可选 | 一个页面加图片文件即可开始，之后按需补充元数据 |

Expo 采用第三种模型。相册拥有页面 URL 和浏览序列，每张图片拥有锚点。
需要长期引用时，作者提供显式 ID。大型收藏由作者自行分册。
当前版本没有资源分页或独立图片数据库。

### 共享外观与紧凑控件 {#shared-appearance-and-compact-controls}

Expo 是一种布局，沿用 Paper、Slate、Ink、Terminal 四种预设及其亮暗模式。
共享的颜色、字体、导航与圆角设置，让相册与站点其余页面保持一致。

三个相邻的单选格同时呈现展墙、卡片和无缝选项，后接播放／暂停按钮和尺寸滑杆。
图标使工具栏保持紧凑，本地化名称、提示与焦点标记支持键盘及辅助技术操作。

读者的显示选择在切换相册和外观后保留。外观控件位于导航中，图片工具栏负责相册操作，
因此相册主体省去文章操作菜单。文字页面中的图片组仍使用 `gallery` 围栏组件。

### 动图与图片查看 {#animation-and-image-viewing}

GIF 默认播放。暂停控件和系统减少动态效果设置提供静态预览，读者也可主动播放。
懒加载减少初始请求，但大型 GIF 仍需传输原始文件。作者组织动图时需要考虑相册体积。

查看器从原尺寸开始，大图缩小到适屏。放大至适屏取宽、高缩放比例中的较小值，
保证整张图片可见。手动缩放、鼠标拖动和 WASD 平移用于查看细节。
Q/E 和 H/L 切换图片，J/K 缩放，R 重置，F 放大至适屏。
这些快捷键只在查看器内处理，避免同时触发页面导航。

原图链接和相册定位链接保留访问与引用能力。原生模态对话框负责约束焦点。
Expo 只在需要的页面加载相册脚本，普通 Image Zoom 保持原有单图行为。
没有 JavaScript 时，读者仍可使用图片链接并阅读说明。

### 稳定布局与共享输出 {#stable-geometry-and-shared-outputs}

占宽度的滚动条会改变网格宽度，新宽度又可能改变行数与总高度。
当相册高度接近视口边界时，这些变化可能导致滚动条反复出现、消失。
这条反馈链造成了报告中的闪烁，即使查看器没有打开也会发生。

Expo 保留滚动条空间，并在模态框锁定页面滚动时保持网格宽度。
回归测试强制启用占宽度的滚动条，采样连续帧。单张截图无法发现这类故障。

HTML、Print、Markdown、LLMSFULL、RSS 和相册封面共用图片解析器，
使各输出的图片顺序与元数据保持一致。静态格式无需查看器脚本即可使用。
修改解析器时，需要检查每一种受影响的输出。

## 验证与归属 {#validation-and-ownership}

主题仓库拥有解析器、布局、脚本、schema 与专项检查。
文档站拥有[双语示例](/zh/expo/)、浏览器测试，以及桌面和手机视觉检查。
验收覆盖四种预设、亮暗模式、键盘输入、焦点、动态效果与静态输出。

Graph 副本提供更大规模的补充证据。最初验收核对了 7,658 个文件哈希、图片锚点，
以及未改动的源收藏。个人图片数据、构建产物与截图位于主题和文档源码仓库之外。

当前验收命令见 [Expo 契约](/zh/docs/design/expo/#acceptance-and-release-boundary)。
