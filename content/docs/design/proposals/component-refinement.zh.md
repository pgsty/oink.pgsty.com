预期结果是让现有组件更加协调，并增加三个可选的内容呈现变体。Paper、Slate、Ink、Terminal 各自保留视觉性格。Ink 与 Terminal 继续作为显式启用的实验预设，本提案不改变它们的稳定性状态。

## 背景与证据 {#context}

[Fluid Functionalism](https://www.fluidfunctionalism.com/)值得借鉴的部分是表面层次、分组行、状态切换与细小的交互处理。主要参考包括它的[表面层次](https://www.fluidfunctionalism.com/docs/surfaces)、[卡片](https://www.fluidfunctionalism.com/docs/card)、[折叠组件](https://www.fluidfunctionalism.com/docs/accordion)、[标签页](https://www.fluidfunctionalism.com/docs/tabs)、[复制控件](https://www.fluidfunctionalism.com/docs/input-copy)和[按钮](https://www.fluidfunctionalism.com/docs/button)。

两个细节尤其适合移植：按压时只移动按钮背景、保持文字稳定；为复制结果预留文字宽度。它的[流动悬停效果](https://www.fluidfunctionalism.com/docs/fluid-hover)也启发了选中背景滑动的想法，但涉及位置测量与生命周期管理，应单独验证。

此前评估检查了公开文档、组件 registry 源码和首页渲染。组件详情页的浏览器检查未能完整完成，因此没有建立参考库在键盘、无障碍或移动端上的验收结论。借鉴方案仍须通过 OINK 自身验证。参考库的八级表面体系、偏小的应用界面排版、依赖 Inter 的字重动画，都不作为移植目标。

OINK 已有相应组件族、原生 Markdown 增强、剪贴板行为和外观系统，精修应进入这些已有实现。已检查的本地版本已经移除了 Paper 标题尾部装饰线，本计划保持这一调整。

## 目标与非目标 {#goals}

1. 让每种预设内部的表面、间距、边框、图标对齐与交互状态保持一致。
2. 先改善读者最常接触的组件，再增加面向作者的新写法。
3. 原生 Markdown 优先；确有表达价值时，通过显式修饰类增加呈现方式。
4. 无 JavaScript 时仍能读取内容，保留键盘、触摸、减少动态效果、打印和机器可读输出的行为。
5. 复用现有样式变量、渲染器、动作处理和运行时模块。

本轮不增加第五种预设、全局密度设置、新的表面引擎或组件注册系统，也不引入 React、Tailwind、Motion、Radix、Base UI 依赖。不增加字体下载或外部 Sass 可执行文件。表单构建器、滑块、颜色选择器、聊天界面、通用弹窗短代码、提示浮层写作语法，以及第三方组件整体换肤均不在范围内。已有博客画廊修改独立处理。

## 共用样式规则 {#style-rules}

### 表面与尺寸 {#surfaces}

围绕三种实际用途组织层次：页面底色、内容表面、浮层表面。优先映射已有色板和组件变量；只有具体组件无法用现有变量表达时，才在既有变量层补充语义明确的 `--td-*` 角色，避免形成第二套配色来源。

独立卡片各自有边界；分组列表使用一个外框和内部分隔线。Tabs 内嵌代码块或表格时，应呈现为一个组合面板，减少重复套框。深色模式主要靠明度与边框区分层次，不能只依赖阴影。

以 4px 节奏辅助检查。图标与文字的间距先从约 8px、行内边距从 12–16px 起步，再用双语样板确认。这些数值作用于组件内部，不构成文章布局的全局重排。保留现有阅读宽度、正文字号、字体选择政策和中文可读性。紧凑控件的视觉尺寸可以较小，但粗指针设备上的有效触摸区域应达到 44×44px，且不能侵占相邻控件。静态徽章和标签不按交互控件处理。

### 状态与动效 {#states}

| 状态 | 拟定规则 |
| --- | --- |
| 默认 | 边界克制、文字清晰；普通内容不暗示可以点击 |
| 悬停 | 轻微改变背景或边框，不移动标题、不改变字重、不引发布局跳动 |
| 选中／当前位置 | 持续可见，并能与悬停状态区分 |
| 键盘焦点 | 立即显示对比度合适的 2px 轮廓，不等待动画完成 |
| 按下 | 对适用按钮只让背景向内收约 1px，文字和点击区域保持固定 |
| 成功／失败 | 预留本地化反馈文字的空间，沿用已有结果提示语义 |
| 禁用 | 保持可读性和现有禁用语义，不单靠颜色表达 |

复用当前 100/150/250ms 三档动效变量，分别承担快速反馈、普通状态变化和少量较大的过渡。按需收敛各组件散落的时长字面值。只对明确属性应用过渡，不引入共用的 `transition: all`。明暗模式和预设切换保持即时。启用减少动态效果时移除位移，但保留可见的状态反馈。

原生折叠块无需强求高度动画，短促的箭头旋转和明确的展开状态已足够。不做文字字重动画，不隐藏未选中的标签页名称。复制操作真正成功后才显示成功；失败反馈应可见，并允许重试。

## 四种预设如何适配 {#presets}

下表圆角是第一阶段的评审起点，尚不是已接受的变量值。共用尺寸规则不能抹平预设之间的差异。

| 预设 | 表面与形状 | 排版与强调 | 动效 |
| --- | --- | --- | --- |
| Paper | 温暖底色、细分隔线、轻阴影；容器约 10–12px，小控件约 6–8px 圆角 | 保留 Plex 阅读体验、蓝色链接与正文留白；不恢复标题装饰线 | 短淡入淡出，按压反馈安静克制 |
| Slate | 保留冻结的基础色板，强化技术面板层次；容器约 12–14px，控件约 6–8px 圆角 | 保留现有 Inter/Chakra/Plex 分工，明确元信息层级 | 最适合试验有限的选中背景滑动 |
| Ink | 直角、精确线条、平面表面，无悬浮阴影 | 保留黑白结构、红色强调和带下划线的链接 | 直接切换状态，不做弹跳或装饰性移动 |
| Terminal | 2px 圆角、平面表面、局部紧凑控件，无悬浮阴影 | 保留等宽界面与标题、Plex 正文、青色链接和琥珀色强调 | 快速、直接，不做装饰性移动 |

站点作者设置的 `theme_color`、字体覆盖、系统字体模式和项目 SCSS 钩子，继续按现有契约保持优先级。不能让共用选择器把 Paper 的圆润与悬浮效果带进 Ink、Terminal。

## 组件修改清单 {#components}

| 组件 | 具体怎样改 | 对写作方式的影响 | 阶段 |
| --- | --- | --- | --- |
| Cards | 对齐图标、标题和说明，统一内边距、边框、悬停与焦点；原生列表和短代码共用视觉规则 | 保留现有网格，后续增加可选分隔列表变体 | 2、3 |
| Callout 与折叠块 | 对齐标记、标题和箭头，让摘要整行形成完整操作区域；中性折叠块更安静，保留警告与错误语义 | 保留既有提示块语法和原生 `details`；不自动把相邻引用块组合成手风琴 | 2 |
| Tabs | 强化选中与悬停的区别，稳定标签尺寸，支持长标签横向滚动，消除内嵌代码／表格的重复边框 | 保留标签文字、分组、哈希／存储行为和键盘操作模型 | 2 |
| 代码与复制控件 | 预留反馈宽度和工具区域，避免遮挡长命令；触摸设备上能直接使用操作；精修成功和失败反馈 | 现有围栏代码块不变，后续增加可选命令条 | 2、3 |
| 表格与 Fields | 调整表头／正文层次、单元格间距、分隔线和对齐；行高亮帮助跟读，不暗示整行可点击 | 保留 `.matrix`、宽表行为、锚点和现有写法 | 3 |
| 徽章与 `kbd` | 修正基线、内边距、边框对比度和各预设圆角 | 沿用短代码和 HTML 路径，不创造新的行内 Markdown DSL | 3 |
| Steps | 精修序号节点与连接线间距，为短流程和静态时间线增加紧凑呈现 | 保留完整教程步骤，可选紧凑修饰类 | 3 |
| 按钮与 Landing 命令框 | 统一形状、只作用于背景的按压、复制反馈和窄屏操作布局 | 复用当前数据与动作处理 | 3 |
| 搜索、命令面板、侧栏、外观菜单 | 对齐图标／标题／元信息／快捷键，统一分组、悬停／当前位置／焦点以及浮层表面 | 不改导航逻辑或偏好存储 | 3 |
| 滑动选中背景 | 只在现有命令面板中试验一块共享的选中背景 | 无新增写作语法，始终可回退到静态状态 | 4，可选 |

纯文字卡片继续作为内容。链接卡片保持正确的链接语义，避免嵌套交互目标。折叠块保持独立操作，首批不需要互斥展开的 FAQ 组。步骤中可以嵌套已有折叠块，静态时间线使用真实日期与状态，不模拟 AI 思考进度。

## 候选 Markdown 变体 {#variants}

第零阶段已确认 Goldmark 属性传递。下列三个变体已在本地实现，并补充所属输出检查和双语示例。公开行为归属组件契约；本页保留原分阶段计划，继续记录暂缓的动效工作。

### 分隔式卡片列表 {#card-list}

```markdown
- [安装](/zh/docs/start/) — 创建本地站点。
- [配置](/zh/docs/customize/config/) — 配置站点。
{.cards .td-cards-list}
```

修饰类将现有卡片列表呈现为单列分组，条目之间使用分隔线，适合相关文章、资源目录和短导航列表。默认卡片网格保持原状。保留条目顺序、说明、链接与移动端换行。

本地完整 `cards` 短代码现已接受 `variant="list"`，不支持的值会警告并回退为默认网格。原生列表和短代码共用表面规则，同时保留各自的 DOM 与输出内容。

### 紧凑命令条 {#command-block}

````markdown
```bash {class="td-code-command"}
hugo server
```
````

复用现有代码渲染器、高亮与剪贴板动作，把明确标记的短命令显示为紧凑条带。保留原文复制及现有 `wrap` 行为。不自动压缩所有单行代码块。多行、带行号或可折叠的代码块继续采用普通代码呈现，并由归属检查给出修饰类不适用的诊断；不能为了塞入条带而丢弃内容。

### 紧凑步骤 {#compact-steps}

```markdown
1. 准备配置。
1. 运行本地预览。
1. 检查生成页面。
{.steps .td-steps-compact}
```

此变体缩小节点和左侧间距，适合短流程、发布摘要与迁移清单。保留有序列表语义、编号、起始值、锚点与嵌套。发布记录已有元数据时直接复用。本地完整 `steps` 短代码现已接受 `variant="compact"`，不支持的值会警告并保持默认呈现。

## 分阶段实施 {#stages}

主线是 **0 → 1 → 2 → 3 → 5**。第四阶段从第三阶段后分出，属于可选试验，不能阻塞第五阶段。第二阶段构成最小有效交付，可以直接进入第五阶段的相应验收，无需等待新增变体或滑动高亮。

### 第零阶段：建立对照基线 {#phase-0}

- 记录两个仓库的 Git 版本、已有修改、模块来源、实际工具版本，以及构建后的 CSS／JS 大小。
- 在真实文档站建立双语对照页面，覆盖 Cards、折叠块、Tabs 和复制控件，包含中文长标签、换行标题、代码／表格嵌套和触摸操作。
- 留存四种预设 × 明暗模式 × 桌面／移动端的对照，覆盖键盘焦点和代表性状态。截图、日志存放在 Git 之外；主题 `tests/site/` 继续只承担合成检查输入。
- 探测三种候选 Markdown 修饰类和短代码归属，确认属性传递、回退与输出影响。

**交付物**：改造前的对照和对应到具体组件的问题清单。**完成条件**：评审标准、样例内容、候选语法可行性和实现边界都已明确。建立样板页面本身不代表视觉改造已获接受。

### 第一阶段：统一组件共用规则 {#phase-1}

- 盘点现有表面、边框、圆角、间距、字体和动效变量，优先复用，只补充实际缺失的组件角色。
- 建立四种预设及深色模式的映射，不改变冻结的 Slate 色板或作者覆盖规则。
- 收敛状态处理和时长，先在一个自有复制／动作按钮上试验只作用于背景的按压，再推广。

**交付物**：小规模共用 SCSS 调整和四种预设映射。**完成条件**：样板在八种预设／明暗组合中状态一致，文字与布局稳定，没有新增依赖或全局密度设置。

### 第二阶段：精修四类样板组件 {#phase-2}

按 **Cards → 提示／折叠块 → Tabs → 代码／复制反馈** 顺序推进，每类形成一次可独立评审的修改。存在原生 Markdown 与完整短代码两种形式的组件同时覆盖；实现、归属检查器和受影响的双语契约一起交付。

**交付物**：四类高频组件完成视觉精修，作者无需改变原有写法。**完成条件**：桌面／移动端、中英文、键盘、触摸、减少动态效果、打印和无 JavaScript 的适用检查通过。这是首个可以独立发布的精修里程碑。

### 第三阶段：增加可选变体并覆盖相邻组件 {#phase-3}

- 探测通过后，将分隔卡片列表、命令条、紧凑步骤拆成三项独立修改，每项包含校验、回退、输出检查和双语作者示例。
- 用已确认的规则精修表格／Fields、徽章／`kbd` 和 Landing 操作。
- 将相同的行布局和状态处理用于搜索、命令面板、侧栏和外观菜单，不改变导航行为。

**交付物**：通过验收的可选变体，以及协调一致的相邻组件。**完成条件**：旧页面无需修改；不适用的输入安全回退；原生和完整形式在视觉上保持一致。任何单个变体都可延后，不阻塞第二阶段或其余变体。

### 第四阶段：试验滑动选中背景 {#phase-4}

首次试验限定在已有命令面板的当前活动行。复用现有选中模型，不根据指针距离另选最近条目，Enter 继续激活原本选中的目标。视觉背景不接受交互，也不能替代即时焦点提示。

使用一个背景元素、缓存的几何信息，并在过滤、尺寸变化、字体变化或滚动后显式更新。不在每个动画帧读取布局，不运行空闲动画循环。沿用现有原生 JavaScript 和运行时边界；减少动态效果时直接切换状态，并保留静态回退。

**交付物**：范围有限的原型，以及前后交互和资源大小的证据。**完成条件**：只有在连贯性确有提升，且没有滞后、错位、选中歧义或新增依赖时才采纳，否则保留静态状态。未来推广到短菜单或 Tabs 需要另行验证，文章列表和卡片网格不在本次试验内。

### 第五阶段：验收与交付准备 {#phase-5}

- 先运行主题的归属检查器，再运行真实站点的 `make check`、`make browser` 和视觉检查；按需核验生产输出，并明确所用模块来源。
- 使用同一构建模式和工具链比较 CSS／JS 大小，解释新增运行时代码的用途；本计划不需要新增框架、远程素材或无条件加载的运行时。
- 更新归属双语契约、写作指南、变更记录和已接受理由。将完成的决策移出提案，按提案生命周期退役已解决内容。
- 发布和下游采纳另行安排。未来发布时使用 `bin/update-consumers.py`，保留维护站点以 Paper 为默认、明确列出四种风格的读者选择政策。

**交付物**：通过验收的实现、文档，以及注明源码来源的验证记录。本地修改、提交、tag、公开模块、消费站 pin 和部署分别记录。编写本计划不执行这些发布动作。

## 实现位置与检查器归属 {#implementation}

## 兼容与输出边界 {#compatibility}

- 既有 Markdown、短代码、组件 ID、URL、Tabs 分组、存储键和作者覆盖保持兼容。新增呈现变体显式启用，不需要批量迁移内容。
- 保留现有 class／参数校验，只通过归属白名单增加必要名称；不支持的输入安全回退。不增加原始 HTML 注入路径、远程获取或内联事件要求。
- 无 JavaScript 时保留全部内容和有效链接；原生 `details` 仍可操作，Tabs 沿用展示内容的既有回退。打印按当前契约展开内容。
- Markdown、LLMS、RSS 输出保留内容和既有语义。呈现修饰类不能让界面控件泄漏到这些输出，不能隐藏步骤、改变复制代码或重复正文。
- 普通使用者继续通过 Hugo Extended 内置 LibSass 构建。项目 SCSS 钩子保持可用，不要求安装可选的 OINK CLI。

## 验收标准与待决问题 {#acceptance}

| 维度 | 所需证据 |
| --- | --- |
| 视觉身份 | 四种预设 × 两种明暗模式 × 中英文；分别确认 Paper／Slate 精修效果和 Ink／Terminal 性格 |
| 响应式 | 代表性 1440、768、390px 视口，加上 320px 溢出检查；长标签和嵌套组件仍可用 |
| 尺寸稳定 | 悬停、按压、复制反馈不移动文字；多行内容自然增高；点击区域互不侵占 |
| 对比度 | 普通文字至少 4.5:1，大字与必要非文字指示至少 3:1；针对实际合成背景测量 |
| 交互 | 检查键盘顺序、即时焦点、适用的焦点返回、持续选中、触摸、强制颜色与减少动态效果 |
| 内容与输出 | 保留现有写法和覆盖、`.matrix`、宽表、锚点、原文复制、无 JavaScript 内容，以及打印、Markdown／LLMS／RSS |
| 等价形式 | 原生 Markdown 和完整短代码变体一起评审，即使 HTML 不同 |
| 运行时代价 | 同构建模式比较 CSS／JS；可选高亮的位置测量有边界，无空闲循环，无新增依赖 |

本地实现已确认上述修饰类名称。共用控件在 Paper/Slate 中采用 8px 圆角，Ink 中采用直角，Terminal 中采用 2px 圆角；容器继续使用所属预设的圆角。第四阶段暂缓，当前静态选中态已满足本次交付，无需增加位置追踪或运行时。未来的 FAQ 分组与发布安排分别决策。
