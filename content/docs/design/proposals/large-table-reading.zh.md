## 为表格增加空间，不缩小文字 {#context}

参数表、扩展矩阵与版本比较超出正常正文宽度的原因各不相同。列数多需要横向空间；行数多需要保持定位；长描述需要换行；合并表头需要保留关联。悬停放大镜不能同时解决这四类问题。[带日期的研究报告](/zh/docs/design/research/2026-10-26-large-table-reading/)比较了五个文档框架、三个表格库，并用真实消费站内容比较三种阅读模式。

有限概念验证中，1440px 桌面视口下的基线表格视口为 653–686px，正文内拓宽后为 1130px，对话框中为 1358px。390px 视口下，基线与正文内拓宽均为 358px，对话框为 374px。正文文字保持 16px，代码保持 14px。这些是概念测量，不是完整外壳或用户研究结果。桌面空间收益值得继续评估；移动端的收益主要是阅读聚焦和操作便利，并非显著增加宽度。

## 选择有清晰返回路径的阅读界面 {#alternatives}

| 方案 | 收益 | 代价与建议定位 |
| --- | --- | --- |
| 正文内拓宽 | 保留正文、链接与浏览器查找上下文；交互成本低 | 受文章可用画布和设备宽度限制。保留现有作者布局控制，作为首选补救。 |
| 接近全视口的原生 `<dialog>` | 在桌面端利用大部分视口，返回文章路径短 | 需要管理焦点、滚动、节点恢复与打印。建议作为首个实验，不调用 Fullscreen API。 |
| 独立阅读页面 | 可提供稳定链接，适合长时间阅读与独立导航 | 增加路由、内容源、翻译、规范链接和输出的维护责任。待分享或持续比较任务确有需求时再推进。 |

不采用表格上方另起一行的操作区。先比较右上角的两个小入口：**A**，安静常驻的展开图标，点击直接进入阅读器；**B**，鼠标悬停表格或键盘聚焦时出现省略号，点击打开小型操作菜单。触屏保留可见的角落入口。两者均保留单元格链接、文字选择与滚动。先确认这两个 Paper 原型，再扩展其他预设或增加操作；入口尚未选定。

## 首期聚焦阅读，数据操作需另有依据 {#scope}

首期提议包括作者显式启用、阅读对话框、舒适间距、可选紧凑内边距和换行、基本粘性表头，以及可选首列固定。暂用标记名为 **`.table-reader`（提议中，尚未实现）**；拼写仍待决定，不是可直接使用的配置说明。只增强符合条件的原生表格，不根据尺寸、`.wide`、`.matrix` 或页面类型自动启用。不增加全局设置，也不自动引入表格库。

排序、筛选、列隐藏、分页、虚拟化、编辑和独立阅读路由不进入首期。版本字符串、单位、空值和有意义的作者顺序需要明确排序语义。筛选和隐藏列会改变比较、复制、打印及查找的内容。虚拟化将屏幕外单元格移出 DOM，需要重新设计浏览器查找、无障碍和输出策略。只有实际任务或性能证据支持时才增加这些能力；24 行样本不能给出虚拟化阈值。TSV 是单独设验收门槛的增强，不是阅读器的前置条件。

## 在一次打开与关闭中保全原表 {#interaction}

打开前，通过 `OinkSurfaceCoordinator` 关闭其他临时界面，且不让它们恢复焦点。同一时刻只打开一个表格阅读器。保存触发按钮、原父节点及后继节点、文章滚动位置和表格容器滚动偏移。插入保持文章几何尺寸的稳定占位节点。原表只移动一次，关闭时恢复同一个节点；重复初始化不得产生嵌套容器或重复监听器。

使用 `showModal()` 及正常的关闭、取消事件。可见标题和关闭按钮位于表格滚动区之外。用 `aria-labelledby` 命名对话框，初始焦点落到带 `tabindex="-1"` 的静态标题上，不给 `<dialog>` 本体设置 `tabindex`。Tab/Shift+Tab 留在模态界面内，Escape 关闭。双轴滚动区要有独立的无障碍名称，并可用键盘聚焦。不要用长串 `aria-describedby` 把整张复杂表格压成一次性朗读。依据见 [WAI 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)与 [HTML dialog 模型](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)。

普通关闭先恢复节点，再恢复容器偏移和文章位置；焦点回到触发按钮，不引起额外滚动。若按钮已移除，使用有明确约定的邻近标题作为回退。协调切换到另一界面时不返回焦点。处理过期关闭事件和异常，避免抢焦点或遗失原表。密度或外观变化期间保留阅读器滚动偏移，并限制在新的有效范围内。再次打开从保存的正文容器偏移开始；精确恢复优先于平滑动画。

保持普通滚动和文字选择，不加拖拽平移、滚轮缩放、缩放变换或双击手势拦截。保留浏览器文字缩放和双指缩放。遵守减少动态效果偏好，使用动态视口高度、安全区域内边距，触屏控件高度至少 44px。在窄屏和放大文字下，工具栏换行不能让关闭按钮无法操作。

## 保留语义与各预设的视觉角色 {#semantics}

保留 `caption`、`thead`、`th`、`scope`、`headers`、单元格链接、代码、ID、语言、书写方向和 DOM 顺序。不把阅读表格转成 ARIA grid。普通题注随表格移动。编号 Book 表格的题注位于外层 `figcaption`，应从中提取纯文本作为阅读器标题，不复制其 ID；若表格原本无名称，临时关联此局部标题，关闭时恢复先前属性状态。

移动节点保留身份与事件状态，但会改变祖先关系。阅读器样式应复现归属表格规则和继承的字体角色，并验证项目自定义样式，而不是复制一份冻结的计算样式。克隆会带来重复 ID、含混的 `headers`、交互状态分叉和浏览器查找重复命中。按数据重新渲染会丢失作者标记。两者都不作为默认替代方案。

先检查引用关系：若作者的 `headers`、`aria-labelledby` 或 `aria-describedby` 依赖可移动表格之外的节点，首期保留正文内阅读并说明增强不可用，除非已验证该关联的交接方案。不能把作者引用悄悄指向不可交互的背景。表格内指向外部脚注或标题的同文档链接，应先关闭并恢复原表，再正常导航；此时不返回触发焦点，以免妨碍到达目标。表格内部链接保留原目标。

| 内容形态 | 首期阅读行为 |
| --- | --- |
| 多列 | 单一双轴滚动区；不造成整页横向溢出，不缩小文字 |
| 多行 | 区域内固定单行表头；保留所有原生行 |
| 长单元格 | 默认舒适换行，可切换不换行以便检查；紧凑模式只改内边距 |
| 多行或合并表头 | 保留原生关联和可读滚动；累计偏移未经验证时，关闭阅读器粘性表头 |
| 宽首列 | 固定首列可选、初始关闭；占视口超过 40% 时禁用，此阈值只是待评审建议 |

Paper 沿用安静的纸面与克制线条；Slate 沿用圆角控件和边框；Ink 使用平面界面与利落分隔；Terminal 控件保留等宽字体，正文与代码仍沿用各自字体角色。四者继承根节点的预设及深浅色令牌，不另设配色，也不缩小文字。Ink/Terminal 仍属实验预设。本提案不重新设计它们的共用契约。

## 为人类可读文本定义有限的复制契约 {#tsv}

若交付 **复制 TSV**，按作者行列顺序复制整张符合条件的表格，包括表头和当前滚动视口之外的行列。复制的是渲染后的人类可读文本，不是原始记录或 URL。链接转为标签文字，代码字符保留为文本。排除隐藏控件和装饰符号。有实际含义的纯图标值需要明确、已本地化的文字等价项；无法恢复其含义时拒绝复制，不能凭图标形状或颜色推断支持状态。

首期只支持单行表头、各行单元格数相同、无嵌套表格，且每个单元格的 DOM `rowSpan` 和 `colSpan` 均为 1 的简单矩形表。任何其他值都应拒绝，明确包括覆盖所在行组剩余行的 `rowspan="0"`。作者隐藏了数据行或列的表格首期不支持，不能静默改变复制范围。可读的合并表仍可进入阅读器，但复制应显示不可用及原因。未来矩形化必须测试跨格位置重复值与留空的规则，不能静默展平合并格。

提议的纯文本 TSV 约定使用 TAB 分隔列、LF 分隔行，末尾不追加行分隔符。将 CRLF/CR 统一为 LF，再把单元格内的 TAB 和换行替换为空格，防止产生额外行列。字面引号保持原样，不采用 CSV 引号规则。保留其他代码字符和空格，同时明确多行代码空白会被规范化。这是便捷导出，不是无损源格式。

序列化前，跳过前导空白或控制字符检查 `=`、`+`、`-`、`@`，命中后在整个单元格前加单引号。这会有意把类似负数和公式的值改为文本。只加引号不能防止公式求值。不同电子表格导入器行为不同，这种前缀只是降低风险，不是通用安全保证。交付前验证预期的 Excel、LibreOffice 与 Google Sheets 粘贴路径。未来显式原始数据或 URL 导出需要单独契约。

只在显式操作后使用 Clipboard API。通过礼貌状态消息报告成功或失败。若缺少安全上下文支持或权限，显示带标签、可选择的只读文本框和手动复制说明，内容使用同一份规范化文本；完成前不能提示成功。暂定 1 MiB UTF-8 载荷上限，仍待测量；超限时说明不可用，不能截断。概念原型的复制 TSV 控件不可用，不能证明本节任何行为。

## 兼容作者标记与静态输出 {#compatibility}

`.wide` 与 `.td-table--wide` 继续只控制布局；短别名是 v1.3.2 之后尚未发布的本地工作。`.full-width` 仍只使用文章可用画布。`.matrix` 保留行表头语义和现有正文内粘性行为；阅读器使用单独验证的粘性策略。`.fields` 输出定义列表，不符合阅读器条件。保留原有类名、编号、标签页、锚点和项目钩子，无需内容迁移。

禁用 JavaScript、资源被阻止或不支持 dialog 时，原有具名滚动区域保持可读，不出现失效入口。专用 Print 保持静态，浏览器预览可滚动，打印媒体展开。Markdown 保留作者表格与属性；RSS 保留原有静态内容或摘要边界，两者都不增加工具栏文字或运行时。阅读器打开时执行浏览器打印，必须在打印布局前同步恢复原表、隐藏临时控件，取消打印后仍可阅读。不能依赖异步 `beforeprint` 工作。

## 明确实现与验收归属 {#implementation}

接受后，在 `oink/layouts/_partials/content/table-render.html` 和 `table-body.html` 中增加仅限 HTML 的资格判断与命名，配合限定作用域的表格 SCSS、本地化标签和按能力加载的小型运行时。复用界面协调约定，不复用图表图片缩放变换。保持 Hugo Extended 0.168.0、Go 1.27.3、内置 LibSass，以及普通消费站仅依赖 Hugo 的构建。实际引入依赖时记录到 `VENDOR.json`；本提案当前不建议新增依赖。

`oink/bin/check-content-primitives.py` 负责输出表格语义、标记、诊断及 HTML/Print/Markdown/RSS 边界。运行时隔离检查与 JS 测试负责按能力加载、状态转换、异常清理，以及纳入范围后的复制序列化。文档站已有的可读性与浏览器覆盖负责真实内容集成和视觉审查；应在那里增加针对性用例，不把 `tests/site/` 变成公开演示。实现验收先跑最窄主题检查器和运行时测试，再运行同级站点的 `make check`、`make browser`，并通过 `make dev` 审阅。保留警告，只在实现同时更新受影响双语契约。这些是未来实现的验收门槛；当前限定范围的研究证据归属[带日期的报告](/zh/docs/design/research/2026-10-26-large-table-reading/)。

## 每种比较都使用相同数据 {#acceptance}

| 范围 | 接受前所需证据 |
| --- | --- |
| 视觉比较 | 同一参数表、扩展包表、版本矩阵分别采用基线，以及正文内拓宽、对话框和独立页面三个概念；覆盖 Paper/Slate/Ink/Terminal × 深浅色 × 桌面/移动端，并有 EN/ZH 对页。页面模式仍只用于研究。 |
| 几何尺寸 | 记录视口、滚动宽度及正文/代码计算字号；无整页溢出；移动端宽度收益必须有测量依据 |
| 输入与焦点 | Enter/Space 打开、标题初始焦点、Tab 循环、Escape/关闭返回、触发器缺失回退、链接、选择、触屏及浏览器缩放 |
| 生命周期 | 重复开关后仍是同一 DOM 节点且 ID 唯一；精确恢复正文容器和页面滚动；无过期事件抢焦点或界面冲突 |
| 结构 | 普通/编号题注、行表头、多行/跨格、脚注、外部 ARIA 引用、标签页/折叠区与项目样式 |
| 无障碍 | 具名对话框/区域、焦点无遮挡、对比度、放大文字、减少动态效果、强制颜色、屏幕阅读器审查及双语针对性 axe 检查 |
| 降级 | 无 JS、资源失败、不支持 dialog、专用 Print、阅读器打开时浏览器打印/取消、Markdown 与 RSS |
| 可选复制 | 标签/代码、图标值、TAB/换行/引号、公式前缀、上限、剪贴板拒绝、礼貌反馈及跨格不支持的可见说明 |
| 兼容与性能 | Chromium/Firefox/WebKit 和触屏审查；引入网格能力前先测真实大行数；记录资源增量与加载范围 |

## 产品选择保留到评审时决定 {#decisions}

待决项包括启用标记拼写、首列宽度阈值、复制载荷上限、TSV 是否进入首个交付门槛、字面 HTML 表格的资格，以及未来可分享路由是否确有需求。概念验证的 16 组几何用例和一次 Paper/浅色/桌面 axe 检查不能关闭这些问题，也不构成无障碍认证。

决策日志，2026-10-26：否定表格上方独立操作区，将入口评审收窄为两个 Paper 角落原型；选定入口前暂缓其他预设变体。保留原生表格对话框方向草案，保持文字尺寸，采用显式入口、单节点恢复和静态回退。继续保留正文内拓宽，独立页面作为已比较的备选方案。未记录实现、API 接受、版本发布、消费站采纳或部署。接受后，按照[提案生命周期](/zh/docs/design/proposals/#lifecycle)，把行为迁入归属契约，把稳定理由迁入 Decisions。
